Done tasks & bugs 
----

- fairness_metrics.py: compute_representation_ratio was returning 0.0 when overall_rate == 0,
  now returns NaN (can't compute a ratio when the group doesn't exist in the population)

- clustering.py: Bug in kprototypes silhouette implementation where we were using the wrong distance matrix (raw Euclidean + gamma * Hamming instead of Gower). Fixed by implementing a custom silhouette function that uses the correct precomputed distance matrix. 
  https://codinginfinite.com/silhouette-coefficient-for-k-modes-and-k-prototypes-clustering/

- experiments.py: continuous sensitive columns like age were being passed through _expand_multiclass_cols, which treated each unique value as a separate category. Then we were applying Kruskal-Wallis to these "categories", which is not appropriate for continuous data. Fixed with a numeric_set branch that routes to Kruskal-Wallis instead (experiments.py:544).

- experiments.py: chi2 rounding issue 

- preprocessing.py / clustering.py: Gower distance + one hot encoding was wrong
  because we were applying one hot encoding before computing Gower, which is redundant and
  causes bias towards categorical features (since one hot ecoded columns get more weight in the distance).
  Fixed by skipping one hot encoding for Gower and computing the distance directly on the
  original mixed data. Ref: https://stats.stackexchange.com/questions/612809/bias-towards-categorical-data-when-one-hot-encoding-and-standardizing-for-machine-learning

- README: added fairness metrics section 
  https://fairlearn.org/main/user_guide/assessment/common_fairness_metrics.html
  https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.entropy.html

- README: added explanation for one hot encoding and StandardScaler in the context of Gower distance, and why we skip them for Gower since it's designed to handle mixed data without OHE or standardization.
  ref: https://stats.stackexchange.com/questions/612809/bias-towards-categorical-data-when-one-hot-encoding-and-standardizing-for-machine-learning

- README: added kprototypes silhouette section explaining why standard silhouette doesn't work
  and what we do instead (precomputed Huang distance matrix)
  ref: https://codinginfinite.com/silhouette-coefficient-for-k-modes-and-k-prototypes-clustering/
